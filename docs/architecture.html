Edgewise architecture

Run the right LLM, the right way, on the hardware you have. Details in docs/SPEC.md.

Four layers. Each layer only depends on the ones below it. The three features share one foundation, so every recommendation, speedup and routing decision is backed by the same measurements.

edgewise bench --model <id> --task <id>: measures how fast a model runs on this device and how well it does real tasks. Every other feature reads from what this writes.

1

Write run manifest

Hardware, git commit, library versions, AC-power status, so any number can be traced back and reproduced.

hardware profilerwarns if on battery
2

Check memory, then load model

Estimate weights + KV cache + overhead. Refuse if it exceeds the budget; record load time and memory after load.

catalogbackend.load()
3

Warm-up

3 throwaway generations so caches and kernels are ready.

repeat 5× per prompt length (128 / 1K / 4K tokens)
4

Performance pass

Stream tokens and timestamp each one. Compute TTFT, prefill tokens/s, decode tokens/s, inter-token latency P50/P95, peak memory.

same timing code for every backend
5

Quality pass

Run every eval item once with greedy decoding and score it: tool-call match, JSON field F1, QA F1, math exact match, or LLM judge for open chat.

eval suitescorers
6

Unload + cool down

Free memory and wait 10 s to reduce thermal effects on the next model.

Results store

edgewise advise --task tool_calling --min-quality 0.9: picks the best model variant for this device and task, and explains why. It only ranks variants that have actually been measured.

1

All catalog variants

e.g. Qwen 2.5 and Llama 3.2 at 0.5B–3B, in MLX 4/8-bit and GGUF Q4/Q5/Q8.

2

Feasibility filter

Drop anything whose estimated memory exceeds the budget (device default or --memory). Mark near-limit ones “tight”.

memory model
3

Look up evidence

Measured quality and speed from the results store. Unmeasured variants are listed with the command to benchmark them, never ranked on guesses.

results store
4

Quality floor

Drop variants below --min-quality (score relative to the highest-precision version of the same model).

5

Pareto frontier

Keep only variants that no other variant beats on both quality and speed.

--prefer speed

Fastest variant above the floor.

--prefer balanced

Default. Maximize quality × speed.

--prefer quality

Highest quality that fits.

✓

Recommendation + explanation

Choice, runner-up and the trade-off in plain words. Rich table, --json, and a Pareto chart for the README.

Speculative decoding on the MLX backend: something cheap guesses k tokens, and the main model checks all of them in one forward pass. With greedy verification the output is identical to normal decoding, just faster.

Draft model

A small model (0.5B/1B) from the same tokenizer family proposes k tokens.

Prompt lookup

Find the latest n-gram in the prompt and propose what followed it. Free, great for RAG and code edits.

loop until max tokens or end of text
1

Propose k draft tokens

k comes from the adaptive controller (1–8).

2

Verify in one pass

Target model scores context + all k drafts at once.

3

Accept matching prefix

Keep drafts while each equals the target's own top choice; add one target token at the first mismatch.

4

Roll back KV caches

Trim draft/target caches to the accepted length.

5

Adapt k

High recent acceptance → raise k. Low → lower it. Near zero → fall back to standard decoding for a while.

✓

Measured per task

Speedup vs. standard decoding, acceptance rate, tokens accepted per step, extra memory, plus a token-for-token test that output is unchanged.

edgewise route "<prompt>" or POST /v1/chat/completions: answer locally whenever possible, escalate to the cloud only when needed, and log every decision with its reason and cost.

1

Request arrives

Messages plus optional tools, JSON schema, or private: true.

2

Hard rules (checked first, can't be overridden)

Private flag or detected PII → local only. Offline → local only. Caller forces cloud → cloud.

PII detectorconnectivity check
3

Routing policy

Chosen in edgewise.toml.

Classifier

Before generating: predict “will the local model succeed?” from prompt embedding + features. Yes → local, no → cloud.

Cascade

Generate locally first. Low mean log-prob or invalid JSON/tool call → escalate to cloud.

Baselines

Local-only and cloud-only, for comparison.

Local model

Fast, private, free. Can use the Accelerator.

Cloud model

Higher quality; tokens × configured prices → cost. Stops at the spend limit.

✓

Response + route log

Answer plus {route, reason, model_id, cost_usd}. Logs feed the cost-vs-quality curve and the % handled locally.
